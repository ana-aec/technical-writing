Project Overview

This framework was developed to resolve documentation inconsistencies across multiple acquired product lines. By enforcing a structured DITA-based matrix, I established a standardized intake process for technical writers, ensuring that all feature releases maintain strict adherence to Concept, Task, and Reference information types.

Beyond the technical configuration, I facilitated cross-functional coordination between Product Management and Engineering to define metadata requirements, significantly reducing downstream review cycles and enabling efficient multi-channel publishing.

CORE RESPONSIBILITIES

  • Information architecture design
  • Single-source template configuration (MadCap Flare)
  • Cross-functional stakeholder coordination
  • CSS class architecture and alert definition
  • Documentation intake standardization

TECHNOLOGY STACK

MadCap Flare • DITA/XML • Custom CSS • Microsoft Word (SME integration)

Authoring Guidelines

Portfolio Note: I designed this strict "delete-as-you-go" workflow to prevent content bloat. By forcing writers to remove unused sections, the resulting output remains concise and avoids the "wall of text" issue common in legacy documentation.
Delete this callout and the entire Template Matrix section before using this template. Also, follow the matrix and delete any section that does not apply to the type of article you're writing. The same applies to the snippets: breadcrumb, navigation buttons, and see also.

Overview

Available in Version: [X.X.X]

This section should provide information on the topic and the article itself. Information on the topic includes any background information such as purpose/use of the feature, users that can benefit from the feature, and, if applicable, its place in the workflow. On the other hand, information on what the article is about includes the purpose of the documentation as well as its outline.

If it's an article for a new feature, the version starting from which the feature is available should be stated in the Available in Version line at the top of this section. Otherwise, delete that line.
